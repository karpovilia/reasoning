# Данные: словарь, опись, манифесты, скачивание

Тела данных в git не хранятся. В git лежат опись, манифесты и скрипт скачивания;
сами файлы трасс и разметки лежат в объектном хранилище и скачиваются командой
make fetch в data/corpora, каталог которого исключён из git.

## Словарь

Трасса — текст рассуждения модели, порождённый прогоном модели на вопросе.
Трасса содержит само рассуждение и ответ. Трассы получаются генерацией, и одна
трасса отвечает одному прогону, а не одному вопросу: у вопроса может быть
несколько трасс, по одной на каждое сочетание модели, ветки прогона и зерна.

Разметка — слой аннотаций поверх готовой трассы. Разметка не порождает текст, а
приписывает к нему события и спаны операторов. Разметку ставит разметчик:
человек, отдельная большая модель в роли судьи или ученик, дообученный на
разметке судьи. Смешивать генерацию и разметку нельзя: это два разных прогона с
разной стоимостью и разными источниками ошибок.

Событие рассуждения — размеченный момент внутри трассы одного из шести типов:
возврат назад, проверка, ветвление, закрытие подцели, признание неудачной
попытки, консолидация.

Сегмент — единица канонической разбивки текста трассы. Разметчик привязывает
событие к номеру сегмента, а не к смещению в символах.

Плечо — одна из сравниваемых веток эксперимента. Два плеча отличаются ровно
одним решением, всё остальное у них совпадает, поэтому разность их исходов
относят к этому решению. Пример: плечо с впрыском и плечо без впрыска в
эксперименте cycle_end_lora отличаются только тем, подмешаны ли в обучение
искажённые примеры.

Цикл — кластер событий рассуждения, замыкаемый консолидацией. Название отсылает
к процессу с самовозбуждением, в котором прошедшее событие поднимает вероятность
следующих. Конец текущего цикла в момент t — ближайшая консолидация строго после
t, а если консолидаций после t больше нет, то конец рассуждения. Остаток цикла —
расстояние в токенах от t до этого конца.

Корпус — именованный набор трасс, полученных одним замыслом прогона, вместе со
своим происхождением. Имя корпуса содержит дату: retrieval_runs_2026_08_16_fixed.

## Опись корпусов

Файл data/registry.tsv. Одна строка описи — один срез трасс вместе с одним слоем
разметки поверх него. Столбцы:

- корпус трасс — имя корпуса;
- trace_model — модель, породившая трассы;
- trace_arm — ветка прогона, то есть набор параметров, отличающий этот прогон от
  соседних;
- trace_seed — зерно генерации;
- trace_bench — бенчмарк, из которого взяты вопросы;
- вопросов бенчмарка в корпусе — сколько вопросов взято и из скольких;
- n_traces — сколько трасс в срезе;
- путь к трассам — где лежит тело трасс;
- labeler_model — кто ставил разметку;
- labeler_mode — режим разметки: окнами, целиком, только события;
- label_pass — какой проход разметки;
- label_dir — где лежит тело разметки;
- размечено трасс — сколько трасс среза размечено;
- label_status — состояние: готово, частично, предварительный, смоук, разметки нет;
- notes — пояснения.

Опись проверяется скриптом tools/check_registry.py: ключ строки уникален,
знаменатели осмысленны, состояние разметки согласовано с остальными столбцами, а
пути существуют, если тело корпуса скачано.

Опись перенесена из чернового рабочего репозитория, файл
docs/registry_traces_labels_2026_08_17.tsv по состоянию на 17 августа 2026 года,
04:14 МСК. Пути в столбцах путь к трассам и label_dir записаны от корня
чернового репозитория; по мере переноса корпусов они меняются на пути внутри
data/corpora, и тогда их начинает проверять check_registry.py.

## Манифесты

Файлы data/manifests/<имя>.json. Манифест перечисляет все файлы набора, их
размеры и хэши sha256, а также описывает архив, которым тело лежит в хранилище:
его имя, размер, хэш и путь объекта. Манифест — единственное место, где записан
состав набора, поэтому скачивание сверяется именно с ним, а не с содержимым
каталога.

Устройство манифеста:

```json
{
  "корпус": "имя набора",
  "описание": "одна фраза, что это",
  "происхождение": "путь к PROVENANCE.md от корня репозитория",
  "собран": "2026-08-17 13:20 МСК",
  "собран_на": "user@192.168.2.43",
  "архив": {
    "объект": "gpb-reasoning/clean/traces/<имя>.tar.zst",
    "имя": "<имя>.tar.zst",
    "размер": 0,
    "sha256": "",
    "корень_распаковки": "<имя>"
  },
  "файлы": [{"путь": "относительный путь внутри корня", "размер": 0, "sha256": ""}]
}
```

## Скачивание

Скрипт data/fetch.sh, вызывается как make fetch.

Данные лежат во внутреннем хранилище, совместимом с S3, в бакете gpb-reasoning.
Адрес хранилища в репозитории не записан: он задаётся локальной настройкой вне
git. Настройка берётся из переменной среды либо из файла в каталоге
~/.config/reasoning-data:

- S3_ENDPOINT либо файл endpoint — имя хранилища так, как его знает клиент, то
  есть начало пути объекта;
- DATA_RELAY_HOST либо файл relay — узел-посредник, необязательный.

Хранилище внутреннее и с рабочей машины напрямую видно не всегда. Скрипт сначала
пробует локального клиента, а если хранилище не отвечает, идёт через
узел-посредник: там клиент кладёт архив во временный каталог, оттуда архив
забирается по scp. Посредник только передаёт файлы и ничего не считает.

Раскладка объектов в бакете:

- gpb-reasoning/clean/traces — тела корпусов трасс, по архиву на корпус;
- gpb-reasoning/clean/labels — тела слоёв разметки поверх корпусов;
- gpb-reasoning/clean/outputs — выходы экспериментов, которым не место в git:
  построчные прогнозы и описи, где встречаются идентификаторы вопросов закрытых
  бенчмарков.

Третий раздел появился не по замыслу, а по срабатыванию проверки. Проверка
tools/check_no_leaks.py нашла в построчных прогнозах двух экспериментов
идентификаторы записей GPQA-diamond и идентификаторы вопросов hle. В репозиторий,
уходящий в удалённый адрес, такие файлы не кладут, поэтому они вынесены в
хранилище и описаны манифестами наравне с корпусами.

Скрипт сверяет хэш архива до распаковки и хэш каждого файла после распаковки.
Несовпадение хоть одного хэша останавливает скачивание.

## Как добавить корпус

1. Собрать архив tar.zst из тела корпуса. Собирать на боксе с картами или на
   рабочей машине, но не на головном узле кластера: там счёта не бывает.
2. Собрать манифест: хэши всех файлов и хэш архива.
3. Залить архив в бакет клиентом объектного хранилища.
4. Положить манифест в data/manifests.
5. Написать PROVENANCE.md корпуса и положить его рядом с экспериментом, который
   корпус породил.
6. Проверить обратное скачивание: make fetch, затем make check.
