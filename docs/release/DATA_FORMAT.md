# Структура трасс и разметки

Дата: 2026-10-02

Выпуск содержит описание данных, конфигурации и схемы. Тексты трасс и разметки остаются локальными. Опись составлена по файлам на диске; сообщения старых сессий не использовались как подтверждение завершения разметки.

## Каталог прогонов

Источник текущего состояния — [catalog.json](../../data/releases/2026-10-02/catalog.json). Он ссылается на 57 файлов `run.json`. Каждый задаёт бенчмарк, точную модель решателя, известную ревизию, настройки генерации, число трасс и отдельные слои разметки. Если параметр не сохранился, записано `null` и пояснение. Версия токенизатора не подменяет неизвестную ревизию весов.

Иерархия повторяет принцип каталога llm_inference: модель, явные настройки и семя читаются из пути. Каждый файл параметров остаётся источником полной конфигурации; короткое имя не заменяет его.

```text
data/corpora/release-20261002/
  <corpus>/<benchmark>/<model_owner>/<model_name>/<settings>/
    run.json
    traces.jsonl.gz
    annotations/<labeler_model>+<checkpoint>+<settings>/
      run.json
      labels.jsonl.gz
  training/
    detector/traces.jsonl.gz
    gate/observer.jsonl
    gate/confidence.jsonl
    gate/labels.jsonl
    gate/ended_population.jsonl
    annotator/train_tok_full.jsonl
    annotator/val_tok.jsonl
```

Например, `repeated-solving/math500/Qwen/Qwen3-4B-Thinking-2507/t100+top_p100+top_k-off+think16384+answer2048+seed101`. Здесь `t100` означает температуру 1.0, `top_p100` — 1.0; `t000` означает жадное декодирование с температурой 0. Полное имя разметчика: `Qwen-Qwen3.6-35B-A3B+ck22000+t000+right16`.

```bash
python -m reasoning_control.data init
```

Команда создаёт только каталоги и конфигурации. Файлы `traces.jsonl.gz` и `labels.jsonl.gz` в схеме выше показывают ожидаемые места будущих данных; сейчас они не скачиваются и не создаются. Старый `data/registry.tsv` описывает прежний архив и не служит списком данных этого выпуска.

## Связь записей

[trace.schema.json](../../data/schemas/trace.schema.json) задаёт формат трассы. `trace_id` — стабильный SHA-256 канонической записи происхождения: корпус, бенчмарк, исходный идентификатор вопроса, идентификатор прогона, семя запроса и хеш исходной строки. Для канонизации используется JSON с сортировкой ключей, UTF-8, `ensure_ascii=False`, `separators=(",", ":")`. Это правило предназначено для будущего нормализованного экспорта; старые внутренние ключи сохраняются в происхождении.

`reasoning` сохраняется без исправлений и нормализации пробелов. `reasoning_sha256` считается по его UTF-8. `question_id` сохраняет исходный идентификатор бенчмарка; его нельзя заменять номером строки. `solver_run_id` указывает на `run_id` соответствующей конфигурации. `source` содержит имя исходного файла относительно рабочего проекта, SHA-256 файла, номер строки и SHA-256 исходной строки без завершающего перевода строки. `correct=null` означает неизвестную оценку, а не ошибочный ответ; `censored=true` — остановку по лимиту.

[annotation.schema.json](../../data/schemas/annotation.schema.json) задаёт отдельный слой разметки. Запись ссылается на `trace_id` и `reasoning_sha256`, а через `annotation_run_id` — на конфигурацию разметчика относительно прогона. `annotation_id` — SHA-256 канонического JSON с ключами `trace_id`, `reasoning_sha256`, `annotation_run_id`, `lo`, `hi`, `source_record_sha256`. Разметка другой версии текста не присоединяется по одному лишь совпадению вопроса.

Идентификаторы вопросов, тексты и ключи отдельных закрытых примеров не входят в опубликованные манифесты. [sources.json](../../data/releases/2026-10-02/sources.json) содержит только пути файлов и контрольные суммы.

## Координаты и качество

Сегмент имеет `seg_id`, исходный `text` и символьный полуинтервал `[char_start, char_end)`. Символы считаются как индексы строки Python Unicode, не как байты. Событие относится к сегменту; спан задаётся полуинтервалом `[seg_start, seg_end)` и типом. Канонические типы перечислены в [архитектуре](ARCHITECTURE.md). Предложенные разметчиком новые типы должны храниться отдельным слоем и не переименовываться молча в канонические.

У окна разметки `[lo, hi)` отдельно записывается видимый контекст `[context_lo, context_hi)`. `available_at_char` — момент доступности всего использованного контекста. Если разметчик видел всю трассу, эта координата равна её длине. `available_at_token=null` сохраняется, когда нет точного соответствия нативным токенам; символьные координаты нельзя выдавать за токенные.

Статусы разметки:

- `accepted`: окно структурно корректно, спаны покрывают его без пропусков и пересечений;
- `partial`: допустимые метки сохранены, но покрытие неполное;
- `quarantined`: ответ нельзя использовать как разметку, например JSON не разбирается или генерация не завершена. Поля принятых событий и спанов остаются пустыми, причина сохраняется в `quality_flags`.

`accepted` не означает человеческую эталонную разметку. Семантические замечания сохраняются в `quality_flags` даже при полном покрытии. Для обучения детектора неполное покрытие представлено масками, а не отсутствием событий.

Проверка формата и согласованности на синтетических примерах:

```bash
python -m reasoning_control.data validate \
  --traces examples/trace.jsonl --annotations examples/annotation.jsonl
```

CLI проверяет связь версий текста, координаты, доступность контекста, типы, дубликаты и покрытие. JSON Schema отдельно задаёт обязательные поля и типы записей. Примеры в `examples` синтетические и не являются выборкой экспериментальных данных.

## Найденные наборы

Числа сохранены в [каталоге](../../data/releases/2026-10-02/catalog.json):

| Набор | Трасс | Трасс со слоем разметки |
|---|---:|---:|
| Сопоставимая панель восьми моделей | 1160 | 1160 DeepSeek Chat; 1015 DeepSeek Reasoner |
| Повторные решения Qwen3-4B-Thinking-2507 | 7880 | 1140 в проверенном обучающем срезе |
| DeepSeek-V4-Flash на HLE, три effort | 6474 | 209 с полным покрытием; 949 хотя бы с частичным |

В первой панели 145 общих вопросов на модель: 69 BBH, 59 MATH500, 17 GPQA. В повторных решениях 788 вопросов по десять запусков; для правильности используется поздняя переоценка от 18 сентября. На HLE один повторяемый служебный запрос исключён из терминальных трасс; полное покрытие не снимает отмеченную необходимость проверки типа `failed_attempt`.

В исходной блочной разметке повторных решений 32 900 блоков, из них 95 с неразбираемым JSON. Аудит также фиксирует некорректные координаты и пропуски. Поэтому число файлов ответов разметчика не трактуется как число чистых размеченных окон. Перед будущей публикацией тел данных потребуется нормализованный экспорт и его проверка по этим схемам.
