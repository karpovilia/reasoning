# Обучение моделей

Дата: 2026-10-02

Команды выполняются из корня репозитория. Трассы и обучающие метки в этот выпуск не входят. [Опись входов](../../data/releases/2026-10-02/training_inputs.json) содержит их исходные имена, контрольные суммы и ожидаемое локальное расположение. Не заменяйте неизвестные метки нулями и не смешивайте части выборки на уровне отдельных попыток решения.

## Подготовка каталогов

```bash
python -m reasoning_control.data init
```

Команда создаёт под `data/corpora/release-20261002` каталоги прогонов, конфигурации и три каталога обучения. Она не скачивает и не создаёт тексты данных. Если существующая конфигурация отличается, команда останавливается. Каталог `data/corpora` исключён из Git.

## Лексический детектор

Источник — проверенный `prepared.pkl` аудита от 24 сентября. Он содержит 1 140 трасс по 114 вопросам, шесть бинарных меток событий на сегмент, маску `event_known` и индекс спана. `-1` обозначает неизвестный спан. У 1 311 сегментов неизвестны события, у 3 579 — тип спана. Это сохраняется при экспорте.

Преобразование доверенного локального артефакта в переносимый вход обучения:

```bash
python tools/release/prepare_detector_training.py \
  --prepared AUDITED_PREPARED_PICKLE \
  --out data/corpora/release-20261002/training/detector/traces.jsonl.gz
```

`AUDITED_PREPARED_PICKLE` заменяется локальным путём к исходному файлу из описи. Порядок трасс сохраняется: он влияет на стохастическое обучение. В каждой строке выходного JSONL находятся `key`, `group`, `fold`, `segments`, `events`, `event_known`, `spans`.

```bash
reasoning-detector train \
  --input data/corpora/release-20261002/training/detector/traces.jsonl.gz \
  --folds 1,2 --seed 20260924 \
  --output outputs/detector/lexical-event-span-v1.pkl
```

Замороженный детектор обучался на частях 1 и 2 — по 23 вопроса. Все решения одного вопроса находятся в одной части. Используются `loss=log_loss`, `alpha=1e-5`, `max_iter=12`, `tol=1e-3`. Рядом с весами сохраняется JSON с хешем входа, гиперпараметрами и количеством известных меток. Код воспроизводит рецепт сохранённой модели; полное переобучение на закрытых данных при подготовке выпуска не запускалось.

## Гейт

Гейт — модель выбора дальнейшего действия по наблюдаемой структуре рассуждения. [Код обучения](../../src/reasoning_control/gate_runtime/fit_pilot.py) принимает три отдельных файла:

- `observer.jsonl`: `key`, `group`, `fold` или `split`, `trace_key`, `now`, завершённые `segments` с нативными токенными координатами;
- `confidence.jsonl`: `key`, `confidence`, `parse_error`; это результат отдельного запроса самооценки;
- `labels.jsonl`: `key`, `action`, `seed`, `content_correct`, `additional_tokens`.

`content_correct` — булев исход либо `null`. `additional_tokens` — наблюдённый расход выбранного действия, а не полная длина решения. Файл `ended_population.jsonl` содержит случаи естественного завершения до контрольной точки; они нужны для оценки всей выборки, но не становятся активными наблюдениями гейта.

Фиксированное разделение: часть 3 — обучение, часть 4 — валидация, часть 0 — тест. Это номера частей для вопросов, а не номера прогонов модели. В опубликованном входе обучения гейта 78 активных префиксов обучения и 26 валидации; для них получено 1 040 исходов действий, восемь оценок правильности остаются неизвестными. Новые вопросы обучающего расширения имеют явное назначение части; их не следует считать той же выборкой из 114 вопросов, на которой обучался детектор.

```bash
python -m reasoning_control.gate_runtime.fit_pilot \
  --observer data/corpora/release-20261002/training/gate/observer.jsonl \
  --confidence data/corpora/release-20261002/training/gate/confidence.jsonl \
  --labels data/corpora/release-20261002/training/gate/labels.jsonl \
  --correctness-field content_correct --cost-field additional_tokens \
  --trainval-only --variants counts_spans,joint --epochs 80 \
  --out outputs/gate_trainval
```

`--trainval-only` запрещает тестовые наблюдения и неиспользованные метки. Параметр `--variants` можно убрать для всех 13 вариантов. Результат включает веса, их JSON-метаданные, контрольные суммы входов, покрытие целей и прогнозы на валидации. Каталог результата должен быть новым.

Обучение использует AdamW, 80 эпох, семена 25, 26, 27 и ширину скрытого слоя 64. Сетка темпа обучения: 0.01 и 0.03 для линейной модели, 0.001 и 0.003 для MLP/GRU; `weight_decay` равен 0 или 0.01. Лучшие эпохи и гиперпараметры выбираются на валидации. [Архитектура и потери](ARCHITECTURE.md) описаны отдельно.

## Калибровка и выбор политики

Обученная голова стоимости возвращает токены. Для критерия в секундах отдельно собираются измерения на валидации. [Код калибровки](../../src/reasoning_control/calibrate_gate.py) переносит исторический выбор по фиксированной сетке цен без обращения к тесту:

```bash
python -m reasoning_control.calibrate_gate \
  --data-root data/corpora/release-20261002/calibration \
  --out outputs/seconds_calibration
```

Под `calibration` нужны `PROTOCOL.md`, `validation_content_v2/records.jsonl`, `observer_cpu_results_v1/predictions_timings.jsonl`, `prompt_budget_v1/validation_predictions.jsonl` и `prompt_runtime_check_v1.json`. Это исходные результаты профилирования; они пока не публикуются. Скрипт проверяет исторический размер выборки: 300 записей, 60 пар «вопрос — семя», по пять действий, только валидация. Для иного протокола требуется заранее изменить ограничения и явно записать новый план.

На валидации выбирается политика при ограничениях на среднее время и 90-й процентиль. Результат `SUMMARY.json` содержит цену, коэффициенты пересчёта, выбранные варианты и признак выполнимости ограничений. Диагностическая конфигурация с `selected_feasible=false` не считается прошедшей ограничение.

Для собственных весов создайте отдельную конфигурацию по образцу `configs/gate/counts_spans.json`: замените путь `weights`, укажите совпадающий `variant`, а `price`, `converter` и `selected_feasible` возьмите из своей валидации. Флаги `needs_confidence` и `needs_structure` должны совпадать с каналами варианта. Существующие конфигурации относятся только к опубликованным весам и измерениям.

## LoRA-разметчик

LoRA — обучаемая добавка низкого ранга к весам базовой модели. [Рецепт полного прогона](../../configs/annotation/training.json) и [код](../../src/reasoning_control/train_annotator.py) сохранены отдельно. Входные JSONL содержат токенизированные `prompt_ids` и `target_ids`: потери считаются только на токенах целевого JSON. Учебный промпт и текст окна маскируются. Полный набор содержит 31 023 окна, полный проход — 7 755 шагов оптимизатора.

```bash
python -m reasoning_control.train_annotator \
  --model BASE_SNAPSHOT_DIRECTORY \
  --train data/corpora/release-20261002/training/annotator/train_tok_full.jsonl \
  --val data/corpora/release-20261002/training/annotator/val_tok.jsonl --val-max 60 \
  --out outputs/annotator \
  --rank 32 --alpha 64 --dropout 0.05 \
  --lr 5e-5 --accum 4 --warmup-frac 0.03 --seed 20260815 \
  --ckpt-every 2000 --max-hours 90 --log-every 20 --save-every 100 \
  --max-memory '{"0": "36GiB", "1": "40GiB"}'
```

`BASE_SNAPSHOT_DIRECTORY` должен указывать на ревизию `995ad96eacd98c81ed38be0c5b274b04031597b0` модели `Qwen/Qwen3.6-35B-A3B`. Полный прогон выполнялся на двух RTX A6000; перед повторением нужен короткий смоук — пробный запуск с `--smoke 2`. Эти команды сами не отправляют задач планировщику.

Для разметки повторных решений использовался сохранённый адаптер `ckpt_022000`. Число в имени — число обработанных примеров, а не шагов оптимизатора. Выпуск сохраняет именно эту промежуточную точку, хотя полный обучающий прогон позже завершился. Не заменяйте её конечной точкой без нового номера слоя разметки.
